数据处理

如果你是为他人部署 Klorn，你就是控制者，Klorn 是你的处理者。我们可以提供数据处理协议——也会给出数据实际经过的所有方的名单，而这恰恰是大多数子处理者页面藏起来的部分。

子处理者

下列各方在运营托管服务的过程中，都可能处理你放入 Klorn 的数据。自托管后，除你选择的模型服务商和 Google 外，其余各行都会去掉。

子处理者职责能看到什么
GoogleGmail 和日历 API，以及登录数据的来源——你的邮箱和日历，限于你授予的权限范围
RenderAPI 托管，新加坡区域API 处理的一切内容，包括传输中和内存中的数据
Supabase托管 Postgres，首尔（ap-northeast-2）所有已存储的账户、邮件和分类数据
GitHub存储每晚的数据库备份（Actions 工件，14 天后过期）仅限加密文件。数据库被复制到一个临时的 GitHub runner 上并在那里加密，只存储密文；用于解密的密钥从不存放在 GitHub 上
Vercel网页应用托管传输中的请求和响应
Google（Gemini API）模型调用为分类或起草而发送的邮件文本，适用禁止用提交数据进行训练的 API 条款
Anthropic（Claude API）模型调用同样的邮件文本，适用禁止用提交数据进行训练的商业 API 条款。默认在 30 天内删除，只有被使用政策执行机制标记的内容才会保留更久
OpenRouter模型路由同上，适用于经由它调用的模型。如果使用你自己的 AI 密钥，这一行就换成你选择的服务商
Paddle支付及记录商家（merchant of record）账单信息。不含邮件内容
Apple推送通知投递（APNs）发往你所注册设备的通知内容

哪些数据绝不外流

Klorn 不出售数据，不用你的邮件训练模型，也不运行第三方分析或追踪器——留存统计只是 Klorn 自己数据库中一份简短的粗粒度事件名白名单，从不包含邮件内容。这一点由 analytics.ts 强制执行，而不只是在这里声明。

直说吧。Klorn 没有 SOC 2 报告，也没有第三方审计。如果你的采购流程要求这些，Klorn 目前无法满足；我们宁愿你在这个页面上就知道，而不是开了三次电话会之后才知道。作为替代，你可以获得以 AGPL-3.0 公开的全部源代码，以及逐一列出强制执行每项主张的文件的安全页面。
