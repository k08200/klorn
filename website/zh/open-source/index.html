“开源”已经成了一个需要核实的词。在这个领域，它常常意味着一份真正的开源许可证，末尾却硬加了各种限制。Klorn 的 LICENSE 就是 GNU AGPL v3，到此为止。

我们划的界线在运维上，而不在功能行为上

Klorn Cloud 出售的是托管服务、一个已完成 Google OAuth 验证的 Gmail 权限范围、可用性保障和事件响应。它出售的不是更好的分类器。注意力防火墙、把每次分类与产生它的确切字节绑定在一起的内容哈希，以及对发送、永久删除和转发到外部所强制执行的回执，在两个版本中完全相同——因为它们就是同一份代码。

如果自托管，你需要自备 Google OAuth 客户端、自己的 Postgres，以及自己的模型密钥或本地模型。配置本地模型后，邮件正文永远不会离开你的机器。

为什么是 AGPL，而不是 MIT

护城河是设计原则和实现上的严谨，而不是许可证。选择 AGPL，是为了让托管的 fork 不能拿掉源码、把防火墙当作闭源服务转卖而不回馈。如果你只是为自己自托管，AGPL 对你的使用方式没有任何影响。

既然选择了 copyleft 许可证，我们就不会再附加条款去削弱它。需要谈判才能获得的许可，并不是 AGPL 所要保护的自由。

与其信任，不如核实。本页的每一项说法都对应一个你可以打开的文件。如果你发现哪一项站不住脚，那就是本页的 bug，我们希望听到你的反馈。

Klorn 还处于早期。仓库如实说明了哪些部分已经扎实、哪些还是拼凑的——CHANGELOG 和 README 中的 “What it's NOT” 一节就是我们维护这份清单的地方。
